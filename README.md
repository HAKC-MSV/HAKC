# HAKC

Instructions for how to build all code and run the ROS2 demo in QEMU.

## Prerequisites

* `Binutils 2.33.1+`
* `aarch64-linux-gnu`

## Set up

1. `bash scripts/support/init.sh`
2. `python3 -m venv python/venv`
3. `source python/venv/bin/activate`
4. `python3 -m pip install -r llvm-project/llvm/utils/hakc/requirements.txt`

## Build LLVM

1. `bash scripts/support/build_llvm.sh`

Creating the initial compartmentalization can be accomplished (assuming the python virtual environment is still active) by

1. `llvm-project/llvm/utils/hakc/hakc-server-process --config cmake-build-hakc/linux/x86/analysis/hakc-config.yaml &`
2. `cd cmake-build-hakc`
3. `cmake --build . --target linux-x86-analysis-pass`
4. `cmake --build . --target linux-x86-enforcement-pass`

The kernel will be built in `cmake-build-hakc/linux/x86/analysis` and the database storing
the compartmentalization policy will be in `cmake-build-hakc/linux/x86/hakc-db`. The
compartmentalization policy is generated by the server automatically once all compilation
is complete. The process started in step 1 will end when the compartmentalization is
finished. Note, this also adjusts the compartmentalization for the ROS 2 demo by default.

## Perform Analysis

1. `llvm-project/llvm/utils/hakc/hakc-server-process --config cmake-build-hakc/linux/x86/analysis/hakc-config.yaml &`
2. `cd cmake-build-hakc`
3. `cmake --build . --target linux-x86-analysis-pass`

## Build the protected Kernel

Note, these directions imply a valid HAKC configuration and policy server configuration is
created, and all paths are correct. See [docs/README.md](docs/README.md) for more
information. Also, hakc-server-process when started in analysis mode with perform all analysis functions, then automatically transition to enforcement mode. 
Using the enforcement/hakc-config.yaml starts the hakc-server-process immediately in enforcement mode. 

1. `llvm-project/llvm/utils/hakc/hakc-server-process --config cmake-build-hakc/linux/x86/enforcement/hakc-config.yaml &`
2. `cd cmake-build-hakc`
3. `cmake --build . --target linux-x86-enforcement-pass`

## Adjusting the compartmentalization for targeted compartmentalization applications

**NB**: This does not need to be done if the default `hakc-server.yaml` configuration file was used for the analysis.

This is an example of how to adjust the initial compartmentalization to suit a specific
application. Adjusting a compartmentalization involves writing a YAML file that instructs
the adjust compartmentalization Python script to adjust the base compartmentalization by
placing symbols together into a compartment, and which other symbols should be placed in
the permissive compartment (named the no enforcement compartment, or NEC).  
The NEC does not perform any checks, but instead ensures that a pointer is valid before
dereferencing it. 
Note that a copy of the database will be created in <hakc-db>-adjusted to keep a clean copy of <hakc-db>.

By default, all symbols are placed in the No Enforcement Compartment (NEC). 
If you want to use a different adjustment configuration, simply copy the preconfigured adjustments yaml to the build directory:

Set rosdemo adjustments:
1. `cp configs/hakc-ros-demo-adjustments.yaml cmake-build-hakc/linux/x86/{analysis, enforcement}/hakc-adjustments`

Set temporal adjustments:
1. `cp configs/hakc-temporal-adjustments.yaml cmake-build-hakc/linux/x86/{analysis, enforcement}/hakc-adjustments`

Finally, adjust compartments:
1. `llvm-project/llvm/utils/hakc/hakc-adjust-compartmentalization-process --config cmake-build-hakc/linux/x86/analysis/hakc-config.yaml`

## Run HAKC test suite standalone / LLVM + HAKC tests 
1. `cd cmake-build-hakc`
2. `cmake --build . --target check-{hakc, llvm}`
